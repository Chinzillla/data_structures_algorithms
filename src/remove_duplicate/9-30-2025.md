## Phase 1: Set up

### Understanding the Question:

Given
- Sorted list of numbers

Expected output:
- length of sorted list of numbers without duplicates
- Remove the duplicates from the original array

### Constraints:
- 1 <= len(nums) <= 3 * 10**4
- -100 <= nums[i] <= 100
- nums is sorted in descending order

### Edge Cases:

Edge case:
- if num has a single number then we can just return 1 immediately
- if the first element and the last element are the same, we can return 1 immediately

### Writing Test Cases:
Example 1:
- input: nums = [1,1,1,1,1,1,1,1,1]
- output: 1

Example 2:
- input: nums = [1,2,3,4,4,5,6]
- output: 6

Example 3:
- input: nums = [100]
- output: 1

## Phase 2: Approach

### Possible Approaches:

Brute Force Approach:

We can have a pointer at a starting point, then traverse through the entire array to see if there are duplicates. If there are then remove. Then move the starting pointer up

Optimized Approach:

We can have a two pointer method where first pointer keeps track of the last distinct element, and everytime it sees a duplicate it does not increment the counter. When we do see a new distinct element we update the first pointer to the new distint element and add 1 to the result.

### Estimated Time Complexity:

Brute Force Approach
- Time complexity: O(n^2)
- Space complexity: O(1)

Optimized Approach
- Time complexity: O(n)
- Space complexity: O(1)

### Best approach:

Best approach is the two pointer approach as mentioned in the optimized path
 
### Skeleton Structure:

1. Cover the edge cases and constraints
2. create a single pointer and a last_seen_duplicate variable
4. pointer will move forward and check for duplicates or new distinct elements
5. When fast pointer sees duplicates, it does nothing and keeps iterating forward
6. When fast pointer sees distinct, it updates the last seen unique element and adds one to result, then proceeds
7. Return the result
